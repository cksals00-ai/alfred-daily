# Alfred Daily 07:00 예약작업 — 인수인계 기록

기준 문서 확인: 이 문서(2026-08-11 작성) · 대상 작업 「Alfred Daily · 교신함 폴링 + 아침뉴스 + 리아 인스타」

이 문서는 **예약작업을 새로 만들면서 넘기는 실행 이력**이다. 작업을 새로 만들면
플랫폼의 실행 로그는 사라지지만, 무엇이 언제 어떻게 돌았고 어디서 깨졌는지는
여기 남는다. 새 작업은 첫 실행 때 이 문서를 한 번 읽고 시작한다.

## 1. 왜 새로 만들었나

**2026-08-09 07:16 이 마지막 정상 실행이다.** 그 뒤로 8/10·8/11 이틀 연속 한 번도
실행되지 않았다. 증거는 세 파일이 같은 날에서 멈춘 것이다.

| 파일 | 마지막 값 |
|---|---|
| `app/public/digest.json` | 2026-08-09 (17꼭지) |
| `app/public/apiusage.json` | 2026-08-09 재현본 37콜 |
| `tools/crawler/freshness.json` | asOf 2026-08-09 |

중간 관측도 남긴다. **8/10 아침에는 다음 실행 시각이 08:17 → 10:32 로 계속 뒤로
밀렸다.** 24시간 주기가 아니라 두 시간 남짓 간격으로 재예약되는 모양이었고,
그날 결국 한 번도 안 돌았다. 8/11 에는 그 재예약조차 잡히지 않았다.
작업은 켜져 있었고 비활성화 사유도 정지 사유도 비어 있었다 — **설정 문제가 아니라
스케줄러 상태가 망가진 것으로 판단**해 같은 프롬프트로 새로 만들기로 했다(alfred 승인).

## 2. 이 작업이 하는 일

1. **교신함 폴링** — 기획실장 → 알프레드데일리 폴더에 새 지시가 있으면 처리.
   리아 인스타 실측치 문서가 오면 `app/public/insta.json` 으로 저장한다.
2. **아침뉴스 재현본** — `tools/crawler/digest.py` 실행 → `digest.json` 갱신 →
   `news.json` 에 그날 항목 추가(`src: "재현본"`). **이미 `src: "원문"` 이 있으면 건드리지 않는다.**
3. **채점** — `tools/crawler/score.py --all` → `rubric.json` 갱신.
4. **리아 인스타 수집기** — 자격증명이 없으면 그냥 넘어간다(정상).
5. **신선도 점검** — `tools/crawler/freshness.py` → `freshness.json`.
6. **커밋 · 푸시 · 배포 · 보고.**

   품질 비교는 반드시 같은 기사 풀에서(`search()` 캐싱 A/B) 한다. **07:00 고정이 중요하다.**

## 7. 새 작업이 지켜야 할 것

- 실행 시각이 07:30 을 넘어가거나 하루라도 결번이 생기면 **보고에 명시**한다.
  조용히 넘어가면 이번처럼 이틀이 사라진다.
- 실패는 실패로 남긴다. **추정치로 메우지 않고 0으로도 채우지 않는다.**
- 시크릿(토큰·키)은 문서·레포·로그·보고문 어디에도 적지 않는다.
  네이버 자격증명은 `website_secrets` 에서 읽고, 깃 푸시 URL 은
  `website_repo_access` 응답에서 받은 것을 그때그때 쓴다.
