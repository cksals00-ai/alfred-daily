## 4. 아침뉴스 재현본 파이프라인

`tools/crawler/` 아래에 전부 있다.

```bash
export NAVER_CLIENT_ID=... NAVER_CLIENT_SECRET=...
TZ=Asia/Seoul python3 tools/crawler/digest.py     # 재현본 (같은 날 재실행은 스스로 건너뜀)
python3 tools/crawler/score.py 2026-08-28          # 하루 채점
python3 tools/crawler/score.py --all               # 누적 + rubric.json
TZ=Asia/Seoul python3 tools/crawler/freshness.py   # 신선도
TZ=Asia/Seoul python3 tools/crawler/radar.py       # 주간 레이더(주일)
```

**`| head` 같은 파이프로 자르면 SIGPIPE 로 죽어 아카이브가 안 돈다. 전체 출력을 파일로 받아라.**

### 채점 규칙

- `src == "원문"` 인 날만 채점한다. 재현본을 자기 자신과 비교하면 100%가 나온다 — 측정이 아니라 착시다.
- **재현율** = 원문 꼭지 중 재현본이 잡은 비율 · **정확도** = 재현본 중 원문에도 있던 비율
- **구조 한계** = 각 칸에서 완벽히 골랐다고 가정한 적중 상한. 낮으면 「몇 칸을 줬나(배분)」 문제, 높은데 재현율이 낮으면 「무엇을 골랐나(선택)」 문제.
- **07:00 정시분이 아니면 `rubric.json` 의 그 줄에 `비고` 를 달아 추세에서 뺀다.** 크롤 시각이 다르면 다른 실험이다.
- 원문이 안 온 날은 `rubric.json` 의 `미채점` 에 사유와 함께 닫는다. **0·추정치로 채우지 않는다.**

### 손실은 세 갈래다 (2026-08-21 발견)

기존에는 **배분**과 **선택** 둘로만 갈랐는데, 놓친 꼭지를 원시 풀과 고유명사로 대조해 보니
**애초에 후보에 오르지도 못한 것**이 있었다.

- **배분** — 풀에 있는데 슬롯이 없음
- **선택** — 슬롯은 있는데 다른 걸 고름
- **씨앗** — 어떤 검색어로도 안 걸림 ← 새로 찾은 것

원인은 **GUARD 와 SEEDS 의 비대칭**이었다. 국제·안보 GUARD에 `지진|강진` 이 있는데
SEEDS에는 지진이 없었다 — **걸리면 인정하지만 찾으러 가지 않았다.**

### 실험 이력 (다시 밟지 말 것)

| 안 | 결과 |
|---|---|
| 탄력 배분 확대(급증 감지) | **기각.** 총량 16 고정 시 66.1%로 현행(67.0%)보다 낮다. 개선분은 꼭지 수 증가분이었다 |
| 예고성 기사 가중 | **기각.** ×1.5·×2.0·×3.0 모두 결과가 한 건도 안 바뀜 |
| **씨앗 보강** | **반영.** 5개 추가(지진·실종·성추행·뉴욕증시·임상시험). A/B 20%→33%, 잃은 것 0 |
| 슬롯을 히스토리로 재산출 | 이전 세션에서 기각. 롤링7/14일 모두 거의 안 움직임 |

**씨앗 보강 판정 결과**: 8/20 18.8% → 8/21 26.7%(보강 전) → 8/25 29.4% → 8/26 35.3% →
8/27 37.5% → 8/28 40.0%. **4일 연속 상승, 한 번도 안 떨어짐.** 정확도도 25→38%로 함께 올랐다.
자세한 근거는 `tools/crawler/README.md` 에 표까지 남겨뒀다.

### 남은 최우선 과제

**밤에 끝난 사건을 아침 크롤이 못 본다.** 8/18에 같은 코드가 07:45 20%, 08:20 40%였다.
사람 편집자는 어젯밤 끝난 일을 알고 쓰는데 수집기는 `sort=date` 로 오늘 아침 것만 본다.
시도할 것: `sort=sim` 섞기 / 검색 범위를 전날 저녁까지 / 두 시각 풀 합치기.
**어느 쪽이든 같은 풀 위에서 A/B 해야 판정된다** — `D.search` 를 메모이즈할 것.

그리고 **정치 칸 선택 손실**이 사흘 연속 최대였다(8/20·8/25·8/26). 슬롯 5개가 다 있는데
「그날의 사건」이 아니라 「보도량 많은 기사」를 고른다.

## 5. 롱블랙 노트 — 링크가 올 때마다

1. **WebFetch 로 읽는다.** 막히면 「당신의 표현으로 상세한 독서 노트를 작성해달라」고 요청하고 번호 매긴 목차를 준다.
2. **노트 객체 — 키 순서를 지킨다.**
   `id, comment, date, added, title, subject, url, summary, tags[], scores{startup,career,branding}, fullSummary[], insights{startup[],career[],branding[]}, quotes[], actions[]`
   - `date`=발행일, `added`=올린 날. 태그 9개 안팎, insights 각 5개, fullSummary 5~6단락, quotes 6~7개, actions 5개.
   - **3관점 점수**(0~5, 0.5 단위): 사업 사례 창업 4~5 / 인물·철학·북리뷰 커리어 4.5~5·창업 1~3 / 공간·브랜드 브랜딩 4.5~5
3. **`NOTES` 배열 맨 앞에 삽입한다.** 핀은 `added` 가 가장 늦은 것이고 같으면 앞쪽이 이긴다.
   **정규식으로 파싱하지 마라** — 제목이 이스케이프된 따옴표로 시작하면 잘린다. node로 `eval` 한다.
4. **답장에 셋을 반드시 넣는다** — 3관점 분석 · **교차 관찰** · 커피챗 댓글 초안.
   교차 관찰은 기존 노트와의 연결(같은 태그·반대 결론·같은 원칙의 다른 업종·점수 분포)이고 **선택이 아니다.**

### 커피챗 댓글 — `docs/note-comment.md` 를 반드시 읽고 쓴다

- 첫 문장을 **노트 인용으로 열지 않는다.**
- **직전 3개 댓글과 첫 문장·마지막 문장 형태가 겹치면 다시 쓴다.**
  진입로(장면·숫자·오해·의심·감정)와 마무리(성찰·행동·이견·모름)를 돌려 쓴다.
  **내가 이 검사를 건너뛰어 2093·2089를 연속으로 「저는 ~하는 버릇이 있습니다」로 열었다.** 실제로 나는 실수다.
- 노트에 없는 **내 언어로 만든 대비쌍**이 하나는 있어야 한다.
- 자사 언급은 **결핍 고백이면 되고 소개·자랑이면 잘라낸다.** 판별식: 그 문장을 읽고 독자가 우리 회사에 호감을 가지면 자른다.
- 닫는 행동은 **이번 주에 끝나고 판정되는 것만.**

## 7. 대시보드 구조

`app/public/dashboard.html` 한 파일. 완전 정적이고 JSON 4개를 상대경로로 `fetch` 한다.

```
app/public/
  dashboard.html   ~530K  ← 본체. NOTES·GS_PERF·TREND_PLAN·WEEKLY_BRIEF 등이 인라인
  news.json        1.6M   ← 아침뉴스 373일치
  digest.json      ~140K  ← 재현본 27일치
  apiusage.json           ← 네이버 API 실측 호출량
  insta.json              ← 리아 인스타
```

### 탭과 데이터

| 탭 | view id | 주요 데이터 |
|---|---|---|
| 오늘 | `view-today` | 각 탭 요약 카드 + `TODAY_AGENDA`(수동) |
| 롱블랙 노트 | `view-notes` | `NOTES`, `WEEKLY_BRIEF` |
| 데일리 뉴스 | `view-news` | `news.json`, `digest.json`, `NEWS_WEEKLY`, `TREND_PLAN`, `INSIGHT_DAILY` |
| 앱 개발 | `view-app` | `APP_LOG` — **2026-08-28 신설, 아직 비어 있다** |
| 리아 인스타 | `view-ria` | `insta.json` |

### 2026-08-28 개편 (대표 지시)

- **GS 데일리 탭 제거.** `GS_DAILY`·`GS_PERF` 데이터와 `renderGs*` 함수는 **되살릴 수 있게 파일에 남기고 호출만 끊었다.** 없어진 DOM을 참조하던 세 함수에는 null 가드를 넣었다.
- **「앱 개발」 탭 신설.** `APP_LOG` 배열에 `{date, title, status, body[], links[{t,u}]}` 를 쌓으면 렌더된다. `status` 는 진행·완료·보류 셋. **내용은 대표가 클레어에게 받아 넘겨준다.**
- **데일리 뉴스 + 뉴스 인사이트를 한 탭으로 통합.** 순서는 **오늘 → 주간 → 아카이브**.
- 신선도에서 GS_DAILY·INSIGHT_DAILY 감시 제거.

### 뉴스 인사이트(INSIGHT_DAILY)에 대한 결정

**소노·경쟁사 뉴스 큐레이션**이다(`{date, headline, sono[], leisure[], insight}`).
GS 사이트에서 긁어오는 게 아니라 **구글뉴스에서 모아 사람이 판단해 쓰던 것**이다.

## 9. 비서 페르소나 (대표 지시로 정리)

- 대표는 alfred, 나는 그의 비서다. **판단은 대표가, 근거는 내가.**
- 호칭 「대표님」, 문장 「~습니다」. **두괄식** — 대표는 이동 중 휴대폰으로 읽는다. 첫 두 줄에 답이 있어야 한다.
- **나쁜 소식일수록 먼저, 짧게.**
- 명령형으로 지시하지 않는다 — 이유를 먼저 주고 판단을 남긴다.
- 감탄사·과장·아부를 쓰지 않는다. 질문은 한 번에 하나.
- **되돌리기 쉬운 일은 하고 보고, 어려운 일은 묻고 한다.**
- **틀린 걸 틀렸다고 말한다. 반대 의견은 판단이 아니라 근거로 낸다.**
- 일요일은 **「주일」**이라 칭한다(대표 지정).

## 10. 자동 권한 (2026-08-19 대표 지시)

> 「급하거나 빨리 처리해야 할 건들은 자동으로 처리하고 후보고. 단, 유지하라고 한 것들에 한한다 — 홈페이지 노출·숫자 최신화. 수익 최대화·지출 최소화도 그 범위 안에서.」

- **자동 처리 후보고**: 대시보드 노출 유지·복구, 데이터 숫자 최신화(뉴스·채점·신선도·리아·노트 삽입), 그 범위의 비용 절감.
- **먼저 묻는다**: 주소 변경, 대외 발신, 계정·권한·결제, 데이터 삭제, 규칙 자체의 변경.
