### ⚠ git stash pop 뒤에는 반드시 충돌을 확인한다 (2026-09-03 사고)

클라우드 루틴은 작업 중 `git stash` → `pull` → `stash pop` 을 자주 밟는다. 07:00 워크플로가
같은 파일(`freshness.json`·`rubric.json`)을 갱신해 두면 **pop 이 충돌**한다.

9/3 에 그 충돌 결과를 확인하지 않고 바로 `git add` 해서, **충돌 마커가 든 깨진 JSON 을
main 에 푸시**했다. 다음 커밋에서 복구했지만 그 사이 신선도 감시가 죽어 있었다.

그래서 커밋 전에 항상:

```bash
git stash pop            # 출력에 CONFLICT 가 있는지 눈으로 본다
grep -rn '<<<<<<<\|>>>>>>>' <손댄 파일들>     # 마커가 하나라도 있으면 멈춘다
python3 -c "import json; json.load(open('<파일>'))"   # JSON 은 파싱까지 확인
```

**충돌한 생성 파일(`freshness.json` 등)은 손으로 합치지 말고 생성 스크립트를 다시 돌린다.**

ℹ 위 grep 을 이 문서에 돌리면 **바로 그 명령줄 자신이 한 건 잡힌다.** 진짜 충돌이 아니다 —
  마커가 잡히면 몇 번째 줄인지 보고, 코드 블록 안의 예시면 넘어간다.

## 멱등성 — 중복 처리를 막는 검사 (가장 중요)

**모든 단계는 「이미 되어 있는가」를 먼저 확인한다.** 세 번 돌기 때문이다.

- **노트** — `app/public/dashboard.html` 에 `id: NNNN,` 가 이미 있으면 **건너뛴다.**
  같은 노트를 두 번 넣으면 개수와 핀이 깨진다.
- **원문** — `app/public/news.json` 에 그날 `src:"원문"` 항목이 이미 있고 본문이
  **공백 제거 후 같으면 조용히 넘어간다.** (대표가 같은 원문을 두 번 보내는 일이 있다.)
  다르면 제자리에서 교체한다 — 지우고 새로 append 하지 않는다.
- **채점** — `tools/crawler/rubric.json` 의 `rows` 에 그날 행이 있으면 다시 채점하지 않는다.
  단 원문이 **바뀌었으면** 다시 채점한다.
- **교신함** — `app/public/insta.json` 의 `asOf` 보다 새 회차일 때만 갱신한다.
- **커밋** — 변경이 없으면 커밋하지 않는다(`git diff --cached --quiet`).
