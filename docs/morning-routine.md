## 왜 레포에 있나

레이더 로직이 히그스필드 예약작업 **프롬프트 안**에만 있다가 플랫폼과 함께 사라진 일이
있었다(2026-08-24 복구, `tools/crawler/README.md` 참조). 그래서 규칙을 세웠다 —
**대시보드를 바꾸는 로직은 레포 안에 둔다.** 이 문서가 그 규칙의 적용이다.
예약작업 프롬프트는 「이 문서를 읽고 그대로 하라」 한 줄이면 된다. 절차를 고칠 때는
프롬프트가 아니라 **이 문서를 고친다.**

## 무엇을 하는가

대표(alfred)가 매일 아침 **제목에 「아침 자료」가 든 메일**로 두 가지를 보낸다.

- **롱블랙 노트 티켓 링크** — `longblack.co/note/NNNN?ticket=...`
- **아침뉴스 원문** — 「📮 …간추린 아침뉴스입니다.」로 시작해 `■` 로 구분된 텍스트

둘 다 올 수도, 하나만 올 수도, 아무것도 안 올 수도 있다.
**없으면 스킵한다. 조르지 않는다.** (2026-08-26 대표 지시)

## 왜 하루 두 번인가

자료가 오는 시각이 일정하지 않고, **07:00 GitHub Actions 가 제때 안 돌 때가 있어서다**
(8/27~8/30 나흘 연속 크게 밀렸다 — 아래 실측 표 참조. 결번이 아니라 지연이다).
두 번 다 같은 절차를 밟되 **이미 처리된 것은 다시 하지 않는다.**

| 시각 | 역할 |
|---|---|
| **07:30** | 본 실행 — 자료 처리, 채점, 파이프라인 확인, 보고 |
| **09:00** | 마감 — 늦게 온 자료 처리 + 밀린 채점 마감 + **오늘의 마지막 문지기** |

### 「결번」이 아니라 「지연」이다 (2026-08-30 실측 정정)

07:00 스케줄이 제때 안 도는 것을 그동안 **결번**이라 적어왔는데, 실행 이력을 시각으로
확인하니 **전부 지연이었고 결국 돌았다.** 지연 폭도 줄고 있다.

| 날 | 스케줄 실제 실행 | 지연 |
|---|---|---|
| 8/27 | 11:51 KST | 4시간 51분 |
| 8/28 | 14:55 KST | 7시간 55분 |
| 8/29 | 12:27 KST | 5시간 27분 |
| 8/30 | 08:51 KST | 1시간 51분 |

그래서 보고에 「결번」이라 쓰지 않는다 — **「N시간 지연」**으로 적는다. 결번은 그날이
끝나도 실행 이력이 없을 때만 쓴다. 없는 실패를 만들어 보고하는 것도 침묵만큼 나쁘다.

**대체 실행의 값어치**: 07:30 대체 실행분(07:3x)이 지연된 스케줄분(08:51~14:55)보다
07:00에 가깝다. 둘 다 「정시분 아님」이지만 이른 쪽이 낫고, `digest.py` 의 같은 날 가드가
뒤에 오는 스케줄분을 건너뛰게 하므로 중복도 안 난다. **대체 실행은 계속한다.**

### 그날 원문이 안 왔을 때 — 판정은 다음 날 아침에 한다 (2026-08-30 규칙)

09:00 마감에서 그날 원문이 아직 없다고 **그 자리에서 미채점으로 닫지 않는다.**
대표가 늦게 보내는 날이 있다. **다음 날 07:30 실행이 「어제 원문이 끝내 안 왔는가」를
판정해 닫는다.** (8/29 원문 미수신을 8/30 아침에 닫은 것이 이 순서다.)

### 07:00 파이프라인이 안 돌았을 때 (2026-08-28 규칙)

`digest.json` 마지막 date 가 오늘이 아니면 **직접 돌린다.**

```bash
TZ=Asia/Seoul python3 tools/crawler/digest.py    # 같은 날 재현본이 있으면 스스로 건너뛴다
```

**클라우드 루틴에서는** NAVER 시크릿이 없어 위 명령이 안 된다 — 대신 `daily-news.yml` 을
`workflow_dispatch` 로 트리거하고 success 를 확인한 뒤 `git pull` 한다. 비고 규칙은 동일.

`digest.py` 에는 같은 날 덮어쓰기 가드가 있어(2026-08-19 반영) 이미 있으면 아무 일도
일어나지 않는다. 안전하게 불러도 된다. **다만 정시분이 아니므로** 채점 후
`rubric.json` 의 그 줄에 `비고` 를 달아 추세 비교에서 뺀다 — 예:
`"비고": "09:12 KST 수동 실행(07:00 Actions 지연) — 정시분 아님, 추세 비교 제외"`.
**0 으로 채우거나 추정치로 메우지 않는다.** 크롤링 시각이 다르면 다른 실험이다.

## 멱등성 — 중복 처리를 막는 검사 (가장 중요)

**모든 단계는 「이미 되어 있는가」를 먼저 확인한다.** 세 번 돌기 때문이다.

- **노트** — `app/public/dashboard.html` 에 `id: NNNN,` 가 이미 있으면 **건너뛴다.**
  같은 노트를 두 번 넣으면 개수와 핀이 깨진다.
- **원문** — `app/public/news.json` 에 그날 `src:"원문"` 항목이 이미 있고 본문이
  **공백 제거 후 같으면 조용히 넘어간다.** (대표가 같은 원문을 두 번 보내는 일이 있다.)
  다르면 제자리에서 교체한다 — 지우고 새로 append 하지 않는다.
- **채점** — `tools/crawler/rubric.json` 의 `rows` 에 그날 행이 있으면 다시 채점하지 않는다.
  단 원문이 **바뀌었으면** 다시 채점한다.
- **교신함** — `app/public/insta.json` 의 `asOf` 보다 새 회차일 때만 갱신한다.
- **커밋** — 변경이 없으면 커밋하지 않는다(`git diff --cached --quiet`).

## 보고를 언제 보내는가

- **처리한 것이 있으면** 채팅 보고 + 지메일 발송.
- **아무것도 없으면** 채팅에 한 줄만 남기고 **메일은 보내지 않는다.**
  하루 세 번 빈 메일이 가면 그 자체가 소음이다.
- 07:30 실행은 처리할 게 없어도 **파이프라인 상태만은** 보고한다(지연·실패 감시가 목적).

### 2-A. 아침뉴스 원문

1. 멱등성 검사(위) 통과 시 `news.json` 에 넣는다. 스키마는 평평한 리스트:
   `{"date":"YYYY-MM-DD","src":"원문","text":"📮 …"}`
   날짜 오름차순 유지, `json.dump(..., ensure_ascii=False, indent=1)`.
   `src` 세 상태(`"원문"`/`"재현본"`/없음)가 채점의 전부다 — 뭉개지 마라.
   원문은 정규식으로 자르지 말고 `text.split('■')` 로 다룬다.
2. **재현본이 있으면** 채점한다. 없으면 위 「07:00 파이프라인이 안 돌았을 때」를 따른다.
   `python3 tools/crawler/score.py YYYY-MM-DD` 와 `--all`.
   **파이프로 자르면 SIGPIPE 로 죽는다 — 전체 출력을 파일로 받는다.**
3. `python3 tools/crawler/freshness.py` 도 돌린다.
4. 채점 결과에서 **그날 발견**을 읽어둔다 — 재현율·정확도·구조한계·배분/선택 손실,
   누락 카테고리, 오탐 패턴. 신규 씨앗(실종·성추행·지진·뉴욕증시·임상시험, 2026-08-21 반영)이
   적중에 기여했는지도 확인한다. 판정 표본이 아직 얇으니 단정하지 말 것.

### 2-B. 롱블랙 노트

1. **WebFetch 로 읽는다.** longblack.co 는 원문 전재를 거부하므로 막히면
   「당신의 표현으로 상세한 독서 노트를 작성해달라」고 요청하고 번호 매긴 목차를 준다 —
   제목·부제·발행일 / 인물·브랜드 연대순 / 챕터별 소제목+핵심 주장 / 숫자·연도·금액 /
   핵심 문장 5~8개 / 프레임워크 / 마무리 질문.
2. **노트 객체 — 키 순서를 지킨다.**
   `id, comment, date, added, title, subject, url, summary, tags[], scores{startup,career,branding}, fullSummary[], insights{startup[],career[],branding[]}, quotes[], actions[]`
   - `date`=발행일, `added`=오늘. 태그 9개 안팎, insights 각 5개,
     fullSummary 5~6단락, quotes 6~7개, actions 5개.
   - 숫자와 인용을 살리고 `<strong>`·`<em>` 으로 강조한다.
   - **3관점 점수**(0~5, 0.5 단위): 사업 사례는 창업 4~5,
     인물·철학·북리뷰는 커리어 4.5~5·창업 1~3, 공간·브랜드 사례는 브랜딩 4.5~5.
3. **`comment` 는 `docs/note-comment.md` 를 반드시 읽고 쓴다.** 핵심:
   - 첫 문장을 **노트 인용으로 열지 않는다.**
   - **직전 3개 노트의 첫 문장·마지막 문장 형태와 겹치면 다시 쓴다.**
     진입로(장면·숫자·오해·의심·감정)와 마무리(성찰·행동·이견·모름)를 돌려 쓴다.
     **직전 3개를 실제로 읽고 대조할 것** — 이 검사를 건너뛰어 두 번 연속 같은 골격으로
     연 적이 있다(2093·2089).
   - 노트에 없는 **내 언어로 만든 대비쌍**이 하나는 있어야 한다.
   - 자사 언급은 **결핍 고백이면 되고 소개·자랑이면 잘라낸다.**
   - 닫는 행동은 **이번 주에 끝나고 판정되는 것만.**
   - 요약하지 않는다. 가르치지 않는다. 동의만 하지 않아도 된다.
4. **삽입** — `NOTES` 배열 맨 앞. 핀은 `added` 가 가장 늦은 노트이고 같으면 앞쪽이 이긴다.

```python
b = json.dumps(note, ensure_ascii=False, indent=2)
b = re.sub(r'^(\s*)"(\w+)":', r'\1\2:', b, flags=re.M)   # 키 따옴표 제거
b = "\n".join("  "+l for l in b.split("\n")) + ",\n"      # 두 칸 들여쓰기
k = s.find("[\n", s.find("const NOTES")) + 2              # 배열 맨 앞
out = s[:k] + b + s[k:]
```

   **NOTES 를 정규식으로 파싱하지 마라** — 제목이 이스케이프된 따옴표로 시작하는 경우가
   있어 잘린다(노트 2069 에서 두 번 틀렸다). node 로 `eval` 해서 읽는다.
   삽입 전후로 `id: NNNN,` 개수를 세어 검증한다.

### 3. 교신함 폴링 (구글 드라이브)

`title contains '리아→기획실장'` 으로 최신 회차를 찾는다
(폴더 parentId `10FNvEm9Pmves7rdE23Mgqa5AFSz14uzM`). `insta.json` 의 `asOf` 보다
새롭고 **실측 지표가 실제로 있으면** 갱신한다.

규칙(기획실장 0730 지시서 v2): **리텐션은 수급값만 쓴다.** 영상 길이가 없으면
계산하지 말고 `len_s` 는 null 로 둔다. **값이 없으면 없다고 적는다 — 0 은 측정된 0 이다.**
`asOf`·`collectedAtKst`·`_source`(문서 ID)·`_notes`(미실측 항목)를 갱신하고
**기존 posts 는 지우지 않는다.** 지표 없는 회차(게시 0 등)는 갱신하지 않고 보고만 한다.

### 4. 파이프라인 확인

- `digest.json` 마지막 date 가 오늘인가
- `https://api.github.com/repos/cksals00-ai/alfred-daily/actions/runs?per_page=5` 에서
  "Daily news (07:00 KST)" 오늘 실행이 success 인가
- `tools/crawler/freshness.json` 신선도
- 라이브 `https://cksals00-ai.github.io/alfred-daily/digest.json` 이 레포와 일치하는가
- **Actions 가 푸시한 날은 Pages 배포가 따라 돌았는지도 본다.** GITHUB_TOKEN 푸시는
  push 트리거를 못 깨운다(재귀 방지) — 8/23~28 내내 스케줄 daily-news 푸시 뒤 배포가
  한 번도 안 돌았고 로컬 예약의 별도 푸시가 가려왔다(2026-08-29 실측). `pages.yml` 에
  `workflow_run` 연결을 넣어 고쳤지만, 배포가 결번이면 `pages.yml` 을 `workflow_dispatch`
  로 직접 돌린다.
- **클라우드 루틴에서는 github.io 직접 조회가 막힌다**(CONNECT 403, 캐시 우회로도 안 된다.
  2026-08-29 실측). 「라이브 조회 불가 + 사유」로 남기고 **배포 SHA 대조**를 대체 증거로 쓴다 —
  이게 배포 success 만 보는 것보다 강하다. 배포된 커밋이 내 HEAD 와 같은지까지 확인되기 때문이다.

```bash
curl -s "https://api.github.com/repos/cksals00-ai/alfred-daily/deployments?environment=github-pages&per_page=1"
# → sha 가 git rev-parse HEAD 와 일치하는지 대조
curl -s ".../deployments/<id>/statuses?per_page=1"   # → state 가 success 인지
```

  둘이 일치하고 success 면 「그 커밋이 라이브에 올랐다」가 확정된다. 추정으로 채우지 않는다.
