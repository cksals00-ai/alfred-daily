# 아침 루틴 — 「아침 자료」 메일 처리 절차

기준 문서 확인: 이 문서(2026-08-26 신설) · 대상 예약작업 3개 (06:00 · 07:30 · 08:00 KST)

## 왜 레포에 있나

레이더 로직이 히그스필드 예약작업 **프롬프트 안**에만 있다가 플랫폼과 함께 사라진 일이
있었다(2026-08-24 복구, `tools/crawler/README.md` 참조). 그래서 규칙을 세웠다 —
**대시보드를 바꾸는 로직은 레포 안에 둔다.** 이 문서가 그 규칙의 적용이다.
예약작업 프롬프트는 「이 문서를 읽고 그대로 하라」 한 줄이면 된다. 절차를 고칠 때는
프롬프트가 아니라 **이 문서를 고친다.**

## 무엇을 하는가

대표(alfred)가 매일 아침 **제목에 「아침 자료」가 든 메일**로 두 가지를 보낸다.

- **롱블랙 노트 티켓 링크** — `longblack.co/note/NNNN?ticket=...`
- **아침뉴스 원문** — 「📮 …간추린 아침뉴스입니다.」로 시작해 `■` 로 구분된 텍스트

둘 다 올 수도, 하나만 올 수도, 아무것도 안 올 수도 있다.
**없으면 스킵한다. 조르지 않는다.** (2026-08-26 대표 지시)

## 왜 하루 세 번인가

자료가 오는 시각이 일정하지 않아서다. 세 번 다 같은 절차를 밟되, **이미 처리된 것은
다시 하지 않는다.** 시각별 차이는 07:00 파이프라인과의 순서뿐이다.

| 시각 | 07:00 재현본 | 그래서 |
|---|---|---|
| **06:00** | 아직 없음 | 원문이 오면 **아카이브만** 하고 채점은 보류. 노트는 정상 처리 |
| **07:30** | 있음 | 본 실행 — 미채점분까지 채점, 파이프라인 확인, 보고 |
| **08:00** | 있음 | 늦게 온 자료 처리 + 앞선 실행이 못 한 채점 마무리 |

## 멱등성 — 중복 처리를 막는 검사 (가장 중요)

**모든 단계는 「이미 되어 있는가」를 먼저 확인한다.** 세 번 돌기 때문이다.

- **노트** — `app/public/dashboard.html` 에 `id: NNNN,` 가 이미 있으면 **건너뛴다.**
  같은 노트를 두 번 넣으면 개수와 핀이 깨진다.
- **원문** — `app/public/news.json` 에 그날 `src:"원문"` 항목이 이미 있고 본문이
  **공백 제거 후 같으면 조용히 넘어간다.** (대표가 같은 원문을 두 번 보내는 일이 있다.)
  다르면 제자리에서 교체한다 — 지우고 새로 append 하지 않는다.
- **채점** — `tools/crawler/rubric.json` 의 `rows` 에 그날 행이 있으면 다시 채점하지 않는다.
  단 원문이 **바뀌었으면** 다시 채점한다.
- **교신함** — `app/public/insta.json` 의 `asOf` 보다 새 회차일 때만 갱신한다.
- **커밋** — 변경이 없으면 커밋하지 않는다(`git diff --cached --quiet`).

## 보고를 언제 보내는가

- **처리한 것이 있으면** 채팅 보고 + 지메일 발송.
- **아무것도 없으면** 채팅에 한 줄만 남기고 **메일은 보내지 않는다.**
  하루 세 번 빈 메일이 가면 그 자체가 소음이다.
- 07:30 실행은 처리할 게 없어도 **파이프라인 상태만은** 보고한다(결번·실패 감시가 목적).

### 2-A. 아침뉴스 원문

1. 멱등성 검사(위) 통과 시 `news.json` 에 넣는다. 스키마는 평평한 리스트:
   `{"date":"YYYY-MM-DD","src":"원문","text":"📮 …"}`
   날짜 오름차순 유지, `json.dump(..., ensure_ascii=False, indent=1)`.
   `src` 세 상태(`"원문"`/`"재현본"`/없음)가 채점의 전부다 — 뭉개지 마라.
   원문은 정규식으로 자르지 말고 `text.split('■')` 로 다룬다.
2. **재현본이 있으면**(06:00 실행은 대개 없다) 채점한다.
   `python3 tools/crawler/score.py YYYY-MM-DD` 와 `--all`.
   **파이프로 자르면 SIGPIPE 로 죽는다 — 전체 출력을 파일로 받는다.**
3. `python3 tools/crawler/freshness.py` 도 돌린다.
4. 채점 결과에서 **그날 발견**을 읽어둔다 — 재현율·정확도·구조한계·배분/선택 손실,
   누락 카테고리, 오탐 패턴. 신규 씨앗(실종·성추행·지진·뉴욕증시·임상시험, 2026-08-21 반영)이
   적중에 기여했는지도 확인한다. 판정 표본이 아직 얇으니 단정하지 말 것.

### 2-B. 롱블랙 노트

1. **WebFetch 로 읽는다.** longblack.co 는 원문 전재를 거부하므로 막히면
   「당신의 표현으로 상세한 독서 노트를 작성해달라」고 요청하고 번호 매긴 목차를 준다 —
   제목·부제·발행일 / 인물·브랜드 연대순 / 챕터별 소제목+핵심 주장 / 숫자·연도·금액 /
   핵심 문장 5~8개 / 프레임워크 / 마무리 질문.
2. **노트 객체 — 키 순서를 지킨다.**
   `id, comment, date, added, title, subject, url, summary, tags[], scores{startup,career,branding}, fullSummary[], insights{startup[],career[],branding[]}, quotes[], actions[]`
   - `date`=발행일, `added`=오늘. 태그 9개 안팎, insights 각 5개,
     fullSummary 5~6단락, quotes 6~7개, actions 5개.
   - 숫자와 인용을 살리고 `<strong>`·`<em>` 으로 강조한다.
   - **3관점 점수**(0~5, 0.5 단위): 사업 사례는 창업 4~5,
     인물·철학·북리뷰는 커리어 4.5~5·창업 1~3, 공간·브랜드 사례는 브랜딩 4.5~5.
3. **`comment` 는 `docs/note-comment.md` 를 반드시 읽고 쓴다.** 핵심:
   - 첫 문장을 **노트 인용으로 열지 않는다.**
   - **직전 3개 노트의 첫 문장·마지막 문장 형태와 겹치면 다시 쓴다.**
     진입로(장면·숫자·오해·의심·감정)와 마무리(성찰·행동·이견·모름)를 돌려 쓴다.
     **직전 3개를 실제로 읽고 대조할 것** — 이 검사를 건너뛰어 두 번 연속 같은 골격으로
     연 적이 있다(2093·2089).
   - 노트에 없는 **내 언어로 만든 대비쌍**이 하나는 있어야 한다.
   - 자사 언급은 **결핍 고백이면 되고 소개·자랑이면 잘라낸다.**
   - 닫는 행동은 **이번 주에 끝나고 판정되는 것만.**
   - 요약하지 않는다. 가르치지 않는다. 동의만 하지 않아도 된다.
4. **삽입** — `NOTES` 배열 맨 앞. 핀은 `added` 가 가장 늦은 노트이고 같으면 앞쪽이 이긴다.

```python
b = json.dumps(note, ensure_ascii=False, indent=2)
b = re.sub(r'^(\s*)"(\w+)":', r'\1\2:', b, flags=re.M)   # 키 따옴표 제거
b = "\n".join("  "+l for l in b.split("\n")) + ",\n"      # 두 칸 들여쓰기
k = s.find("[\n", s.find("const NOTES")) + 2              # 배열 맨 앞
out = s[:k] + b + s[k:]
```

   **NOTES 를 정규식으로 파싱하지 마라** — 제목이 이스케이프된 따옴표로 시작하는 경우가
   있어 잘린다(노트 2069 에서 두 번 틀렸다). node 로 `eval` 해서 읽는다.
   삽입 전후로 `id: NNNN,` 개수를 세어 검증한다.
