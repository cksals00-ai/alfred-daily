# 아침뉴스 재현본 파이프라인

기준 문서 확인: 이 문서(2026-08-03 신설)

## 이게 뭔가

alfred 가 매일 받는 「간추린 아침뉴스」를 자동으로 재현해 보고, 그가 붙여넣은
**원문과 대조해 점수를 매기고, 그 점수로 다음 날 수집 규칙을 고치는** 루프다.

```
digest.py  수집·편집 → app/public/digest.json   (재현본, 날짜별)
              ↕ 대조
alfred 붙여넣기 → app/public/news.json          (원문, src:"원문" 로 표시)
              ↓
score.py   채점 → rubric.json                   (재현율·정확도·누락 카테고리 누적)
              ↓
           digest.py 의 SLOTS / SEEDS / GUARD 를 고친다
```

## 왜 레포 안에 있나

예약작업은 매번 **새 컨테이너**에서 레포를 클론해 돌린다. 이전에는 이 스크립트가
`/home/claude/work/crawler/` 에만 있어서 예약 실행 때 없는 파일이었고, 그래서
2026-08-01 부터 재현본이 웹검색 수기 수집으로 대체되며 꼭지 수가 16 → 9 → 5 로
떨어졌다. 레포 안에 두면 클론만으로 항상 존재한다.

자격증명은 레포에 넣지 않는다(공개 저장소다). `_paths.cred()` 가 환경변수 →
작업폴더 `.naver.json` 순으로 찾고, 둘 다 없으면 **추정하지 않고 예외를 낸다.**

## 채점 규칙

- `src == "원문"` 인 날만 채점한다. 재현본을 news.json 에 그대로 써 넣은 날을
  채점하면 자기 자신과 비교해 재현율이 100% 로 나온다 — 측정이 아니라 착시다.
- **재현율** = 원문 꼭지 중 재현본이 잡은 비율 (놓친 사건을 본다)
- **정확도** = 재현본 꼭지 중 원문에도 있던 비율 (헛다리를 본다)
- 매칭은 어간 기준 핵심어 겹침이다. 한국어 조사 때문에 `여객선` 과 `여객선에`
  가 다른 토큰이 되므로 뒤 한두 글자를 떼어 함께 비교한다.
- 매칭은 완벽하지 않다. **같은 주제·다른 각도**(예: 원문 "구마모토 반도체 공장
  재가동" ↔ 재현본 "구마모토 강진 수색 종료")는 누락으로 잡힌다. 점수는 절대값
  보다 **추세**로 읽는다.

## 지금까지 확인된 것 (2026-08-03 기준, 정본 1일)

재현율 12% · 정확도 40%. 누락 카테고리는 정치·국회 4, 사건·사고 4, 국제·안보 3,
경제·시장 2, 부동산 1, 날씨·기후 1.

원문과 재현본의 성격 차이가 구조적으로 드러난 부분:

1. **원문은 "오늘 무엇이 예정돼 있나"를 쓴다.** 재현본은 어제 보도량이 많았던
   기사를 쓴다. 원문 1번 꼭지가 "귀국 직후 점검 회의를 엽니다"인데 재현본은
   "귀국했다"를 잡는 식이다. → `sort=date` 만으로는 예고성 기사를 못 잡는다.
2. **원문은 생활·사건·사고를 많이 쓴다.** 신림동 상가 화재, 군산 방사선사,
   차은우 조세심판 — 보도량은 적지만 사람들이 읽는 것들이다. 재현본의 슬롯
   배정(정치 5)이 실제 분포와 다르다.
3. **원문은 숫자를 꼭 넣는다.** "온열질환자 96명 늘어 누적 1,889명, 사망 14명".
   재현본은 제목·요약을 그대로 옮겨 숫자가 빠진다.
4. **원문은 두 문장으로 재작성한다.** 재현본은 네이버 요약문을 그대로 쓴다.

## 신선도 점검 (freshness.py)

score.py 가 "재현본이 얼마나 정확한가"를 본다면, freshness.py 는 그 앞의 질문 —
**"애초에 갱신이 돌긴 했는가"** — 를 본다. 둘은 다른 실패다. digest.py 가 컨테이너에서
사라진 채 몇 주를 돌았을 때 화면은 멀쩡했다. 어제 데이터가 남아 있으면 오늘 것처럼
읽히기 때문이다. 그 침묵을 깨는 게 이 스크립트다.

12개 소스의 **최신 날짜만** 읽는다. 담당 예약작업을 함께 찍어서, 멈춘 축이 있으면
어느 작업을 봐야 하는지가 바로 나온다.

| 축 | 담당 예약작업 | 임계(정상/주의) |
|---|---|---|
| news.json · digest.json | Alfred Daily 07:00 `trig_01QSnb9cSoQyNvLku62aKCA4` | 1일 / 2일 |
| insta.json | 같은 작업 §0 (교신함 수급) | 1일 / 2일 |
| GS_DAILY · INSIGHT_DAILY | GS·인사이트 09:00 `trig_01QM65z2VTBqfM4AB5Zgd9dD` | 1영업일 / 2영업일 |
| GS_PERF.asOf | 같은 작업 §1-b | 2영업일 / 3영업일 |
| GS_PERF.fcstAsOf | 같은 작업 (주간 스냅샷) | 7일 / 10일 |
| TREND_PLAN | 같은 작업 §3 (일요일만) | 7일 / 9일 |
| WEEKLY_BRIEF · NEWS_WEEKLY | 주간 브리핑 일 07:00 `trig_01NqusWzxt6ikGFZkKwRJ15C` | 7일 / 9일 |
| NOTES · TODAY_AGENDA | 없음 — 손으로 채운다 | 수동(참고만) |

설계상 지켜야 할 것 세 가지.

1. **GS 계열은 달력일이 아니라 영업일로 센다.** 출처 페이지가 주말·공휴일에 갱신되지
   않기 때문이다. 토요일마다 "하루 밀렸다"고 울리는 경보는 곧 아무도 안 본다.
2. **GS_PERF.asOf 는 임계를 한 칸 밀어 놓았다.** 출처가 전일 실적을 싣는 구조라
   1영업일 지연이 정상이다. 구조적 지연을 고장으로 부르지 않는다.
3. **수동 축은 실패로 세지 않는다.** 롱블랙 노트는 alfred 가 링크를 보낼 때만 늘어난다.
   공백은 고장이 아니라 그냥 공백이다. 경과일은 보여주되 판정은 「수동」으로 남긴다.

파일·상수를 못 읽으면 「조회실패 + 사유」로 남기고 넘어간다. 0으로도, 추정치로도
채우지 않는다.

### 기각 ① 탄력 배분 확대 (급증 감지)

기준 정본에서 기본 슬롯을 넘긴 카테고리를 모두 늘리는 안. 정본 12일 백테스트

| 규칙 | 평균 구조 한계 | 평균 꼭지수 |
|---|---|---|
| A 현행 | 67.0% | 16.25 |
| B1 급증 감지 | 69.3% | 16.67 |
| B2 급증(기증자 포함) | 66.5% | 16.08 |
| B3 트리거 1/4 | 67.5% | 16.58 |
| C 배분 끔(대조) | 65.0% | 16.00 |
| 오라클(그날을 알고 배분) | 95.9% | 16 |

B1 이 +2.3%p 로 보이지만 **총량을 16으로 고정하면 66.1% 로 현행보다 낮다.**
개선분은 배분이 아니라 꼭지 수가 늘어난 데서 왔다. 대조 실험이 그걸 확인해 준다 —

구조 한계는 꼭지가 많아지면 그냥 오르는 값이라 총량을 통제하지 않은 비교는 무효다.
(총량을 늘리는 것 자체도 답이 아니다. 원문 평균이 15.9꼭지라 18을 만들면 최소 2건은
오탐이 되고 정확도가 떨어진다. 재현율만 보는 지표 게이밍이 된다.)

백테스트 자체의 타당성은 실측으로 확인했다 — A 현행의 날짜별 값이 `rubric.json` 에
기록된 구조한계율과 **10일 중 8일 정확히 일치**(평균 절대오차 1.8%). 어긋난 8/5·8/6 은
슬롯을 줬는데 후보가 안 잡혀 칸이 빈 날이다.

**중요**: 8/21 은 B1 도 67% 로 현행과 같다. 그날 문제였던 날씨 3꼭지(거제·통영·태풍)는
기준 정본(8/20)에 날씨가 1꼭지뿐이라 어떤 이력 기반 규칙으로도 예측되지 않는다.
**「카테고리 구성은 과거로부터 예측되지 않는다」가 다시 확인됐다.**

### 기각 ② 예고성 기사 가중

원문은 「오늘 무엇이 예정돼 있나」를 쓰는데 재현본은 보도량 순으로 고른다는 진단에서,
제목·요약에 예고 표지(오늘·예정·열린다·참배·논의…)가 있으면 보도량 가중치에 배수를
주는 안. 같은 풀 A/B (메모이즈, 8/21 정본 대상):

| 설정 | 재현율 | 정확도 |
|---|---|---|
| A 현행(보도량순) | 27% | 25% |
| B ×1.5 / ×2.0 / ×3.0 | 27% / 27% / 27% | 25% |

**세 배수 모두 결과가 한 건도 안 바뀌었다.** 순위를 흔들어도 정답이 후보에 없으면
소용이 없다는 뜻이고, 이게 아래 발견으로 이어졌다.

### 반영 ③ 씨앗 보강 — 세 번째 손실을 찾았다

지금까지 손실을 **배분**과 **선택** 둘로만 갈랐는데, 놓친 꼭지를 원시 풀(1,260건)에
고유명사로 직접 대조해 보니 **애초에 후보에 오르지도 못한 것들**이 있었다.
8/21 놓친 11꼭지의 분해:

- **배분** — 풀에 있는데 슬롯이 없음: 날씨 3(거제·통영·태풍 사우델, 슬롯 1개)
- **순위** — 슬롯이 있는데 다른 걸 고름: 김민석 통합행보·용산공원·미 재무부 국채 등
- **씨앗** — 어떤 검색어로도 안 걸림: 페루 강진 · 제주 30대 실종 · 연세대 성추행

원인은 **GUARD 와 SEEDS 의 비대칭**이다. 국제·안보 GUARD 에는 `지진|강진` 이 있는데
SEEDS 에는 지진 씨앗이 없었다. **걸리면 인정하지만 찾으러 가지는 않았다.**
사건·사고도 씨앗이 구속·화재·사망 셋뿐이라 실종·성범죄가 통째로 빠졌다.

같은 시각·같은 원문 A/B (신규 씨앗 5개: 지진 / 실종 · 성추행 / 뉴욕증시 · 임상시험):

| 설정 | 재현율 | 정확도 |
|---|---|---|
| A 현행 씨앗 | 20% | 19% |
| B 씨앗 보강 | **33%** | **31%** |

새로 잡은 것 2건(페루 강진 · 연세대 성추행), **잃은 것 0건.** API 콜 42 → 47.
씨앗 추가는 후보를 늘릴 뿐 기존 후보를 지우지 않아 구조적으로 잃을 것이 없다.
그래서 반영했다. 다만 **1일 표본이다** — 새 후보가 다른 날 기존 후보를 순위에서
밀어낼 수 있으므로 며칠 관측 후 재판정한다.

**주의**: 이 A/B 의 A(20%)와 위 ②의 A(27%), 07:00 정시분(27%)이 서로 다르다.
크롤 시각이 다르면 기사 풀이 다르기 때문이고, **같은 표 안의 A vs B 만 비교해야 한다.**

## 원문이 안 오는 날 (2026-08-25 규칙)

alfred 가 원문을 못 보내는 날이 있다. 주말이 특히 그렇다. 처리는 이렇다.

- **재현본은 평소대로 만든다.** 07:00 실행은 원문과 무관하게 돈다.
- **채점은 하지 않는다.** `score.py` 는 `src == "원문"` 인 날만 채점한다 — 재현본을
  자기 자신과 비교하면 100% 가 나오고 그건 측정이 아니라 착시다.

  0 으로도, 추정치로도 채우지 않는다.
- **아침 보고는 원문을 3일까지만 요청한다.** 그 이상 지난 날짜는 조르지 않고 넘긴다.

## ⚠ 재현율 하나만 보고 판단하지 마라 (2026-09-03 실측)

정본 17일치로 상관을 재보니 **원문 꼭지 수와 재현율이 뚜렷한 음의 상관**이었다
(r = -0.557). 재현본은 늘 16꼭지 고정인데 원문은 13~17꼭지로 흔들리므로,
**원문이 짧은 날은 분모가 작아 재현율이 저절로 올라간다.**

| 원문 꼭지 | 일수 | 평균 재현율 |
|---|---|---|
| 13 | 1 | 53.8% |
| 14 | 1 | 57.1% |
| 15 | 3 | 35.6% |
| 16 | 5 | 40.0% |
| 17 | 7 | 29.4% |

**적중 절대수**는 원문 길이에 덜 흔들린다(r = -0.344). 그리고 그 숫자는 실제로 늘었다 —
8/20 3건 → 8/25 5건 → 8/27~28 6건 → 9/2 **8건(역대 최다)**. 씨앗 보강이 헛것은 아니었다.

그래서 규칙:

- **보고에 재현율만 쓰지 않는다.** 「재현율 N% (적중 M건 / 원문 K꼭지)」로 세 숫자를 함께 적는다.
- 하루치 등락으로 개선·악화를 단정하지 않는다. 9/2 의 57% 는 절반이 실력(적중 8건),
  절반이 분모(14꼭지)다. 8/31 의 31% 도 적중 5건으로 8/28(6건)과 큰 차이가 아니었다.
- 「씨앗 보강 후 4일 연속 상승(29→35→38→40%)」이라는 기존 판정도 **부분적으로 분모 효과**였을
  수 있다. 그 기간 원문은 17·17·16·15 꼭지로 계속 짧아졌다. 기각하지는 않는다 —
  적중 절대수도 5→6→6→6 으로 같이 올랐기 때문이다. 다만 「4일 연속 상승」이라는 표현은 과했다.

⚠ 분모 효과와 그날 사건 성격(큰 사건이 몰린 날은 원문도 짧고 재현본도 잘 맞춘다)이 뒤엉켜
있어 둘을 완전히 분리하지는 못했다. 확정된 것은 **재현율 단독 해석이 위험하다**는 것뿐이다.
