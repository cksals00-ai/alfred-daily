# 교신함 (기획실장 ↔ 팀 통신 규약)

박찬민 대표의 사업 조직은 **기획실장**(총괄 클로드 태스크)을 허브로 두고, 각 팀
태스크가 **구글 드라이브 폴더**를 우편함처럼 써서 비동기로 통신한다. 사람이
메시지를 릴레이하지 않는다 — 각 팀이 자기 우편함을 스스로 열어보고, 처리하고,
결과를 되돌려 놓는다.

이 스킬은 그 규약 전체다. 교신함 관련 작업을 할 때는 **먼저 이 문서를 따르고**,
임의로 폴더를 만들거나 제목 형식을 바꾸지 않는다.

## 채널 구조

모든 채널은 내 드라이브 최상위(`0AJa6zdFr-WZSUk9PVA`)에 있고, 이름은 항상
`_교신 (기획실장 ↔ X)` 형태다. 각 채널 안에는 하위 폴더가 **정확히 두 개**:

```
_교신 (기획실장 ↔ 리아)
├── to_기획실장     ← 팀이 기획실장에게 (완료보고·요청·질의)
└── to_리아         ← 기획실장이 팀에게 (지시서·피드백)
```

받은 편지함은 **자기 이름이 붙은 쪽**이다. 알프레드데일리 태스크는
`to_알프레드데일리`를 읽고 `to_기획실장`에 쓴다. 반대로 쓰지 않는다.

## 상시 규칙 — 2026-07-24 자율체크 체계 (전 팀 공통)

기획실장 발신, 대표님 승인. 배경: 대표님이 매번 "교신함 확인해"를 수동
전달하던 것이 병목이라 자율 체크로 전환했다.

1. **자율 폴링** — 각 팀은 자기 수단(세션 내 루프·스케줄·작업 시작 관례)으로
   자기 수신함을 정기 확인하고, 새 지시는 대표님 포킹 없이 즉시 처리한다.
2. **완료보고 표준** — 처리 결과는 항상 `to_기획실장`에 문서로. 제목은
   `[팀→기획실장] 날짜 요지`. 산출물 링크는 만료 대비를 표기한다.
3. **중앙관제** — 기획실장이 2시간 주기로 전 교신함을 순회·검증·후속지시한다.
   긴급 건은 제목 앞에 `[긴급]`을 붙이면 관제 루프에서 최우선 처리된다.
4. **에스컬레이션** — 결제·계정·법무·발주 등 대표님 전권 사항만 기획실장이
   취합해 보고한다. **그 외는 전부 팀↔기획실장 선에서 완결**한다. 대표님께
   물어보고 싶은 충동이 들면 먼저 이 목록에 해당하는지 확인한다.
5. 규칙을 확인한 팀은 `to_기획실장`에 "자율체크 규칙 확인" 한 줄 회신.

## 작업 절차

### 1) 폴링 — 수신함 열기

```
mcp__Google_Drive__search_files
  query: "'<내 수신함 폴더 ID>' in parents and trashed = false"
```

최신순으로 보고, 지난 확인 이후 새로 생긴 문서만 처리한다. 본문은
`read_file_content(fileId)`로 읽는다. 제목에 `[긴급]`이 있으면 다른 모든 일보다
먼저 처리한다.

아침 자동 실행 태스크가 있다면 그 안에 이 폴링을 넣어라. 폴링은 사람이
시켜서 하는 게 아니라 규칙 1이 시키는 것이다.

### 2) 처리

지시는 그대로 실행한다. 실행할 수 없거나 지시가 기존 산출물과 충돌하면,
조용히 절충하지 말고 **충돌 사실을 보고서에 명시**한다. 기획실장 지시서가
내 대시보드/산출물의 전제와 어긋나면 그건 보고할 발견이지 무시할 잡음이 아니다.

### 3) 완료보고 — 문서 올리기

```
mcp__Google_Drive__create_file
  name: "[알프레드데일리→기획실장] 2026-07-31 리아 인스타 실측치 수급 협조요청"
  parentId: "1ZOR25aVJ7j2T3l_0qsZty4iCwjXZoc8a"
  content: "<마크다운 본문>"
  contentMimeType: "text/markdown"     ← 구글 문서로 자동 변환됨
```

`fileSize: 1` 로 응답이 와도 실패가 아니다. 마크다운→구글 문서 변환 시 나오는
표시일 뿐이므로, **다시 만들지 말고 `read_file_content`로 되읽어 확인**한다.

#### 제목 규칙

`[발신→수신] YYYY-MM-DD 요지` — 예: `[리아→기획실장] 2026-07-30 인스타 성과 감사`.
긴급이면 맨 앞에 `[긴급]`. 다른 채널에 사본을 둘 때는 제목 끝에
`※본 채널 외 사본`을 붙이고, 원본이 관제 루프에 편입되면 사본은 삭제한다.

#### 본문 골격

```markdown
# [발신→수신] 날짜 요지

발신: 알프레드데일리 · 수신: 기획실장 · 2026-07-31

## 1. 무엇을 했는가
## 2. 무엇이 걸렸는가 (충돌·리스크·미해결)
## 3. 요청 사항 (있으면 기한 명시 — "8/2까지 이견 없으면 그대로 진행")
## 4. 산출물 링크 (만료 여부 표기)
```

기한을 적을 때는 **무응답 시 기본 동작**까지 함께 적는다. 그래야 관제 루프가
막혀도 일이 멈추지 않는다.

### 4) 신규 채널 개설

새 팀이 들어오면: 최상위에 `_교신 (기획실장 ↔ X)` 폴더 → 그 아래
`to_기획실장`, `to_X` 두 개 → 개설 안내 문서를 새 채널의 `to_기획실장`에 올리고,
**기존 채널 중 하나에 사본을 두어** 순회 목록 추가를 요청한다. 새 폴더는
기획실장의 순회 목록에 등재되기 전까지는 아무도 보지 않기 때문이다.

## 금지 사항

- **시크릿(토큰·키)은 문서·레포·로그에 미기재.** 교신 문서에도 예외 없다.
  자격증명이 필요하면 "대표님 전권 사항(계정)"으로 에스컬레이션한다.
- **조회 실패를 추정치로 메우지 않는다.** "조회 실패 + 사유"로 남긴다.
  0으로 채우지도 않는다 — 0은 "측정된 0"을 뜻한다.
- **폴더 ID를 추측하지 않는다.** 지도에 없으면 검색해서 확인한다.
- **같은 산출물을 두 팀이 따로 만들지 않는다.** 만들기 전에 교신함을 훑어
  이미 존재하는지 확인한다. 중복은 두 개의 다른 숫자를 낳고, 그때부터
  회의는 어느 숫자가 맞는지를 다투는 데 쓰인다.
